On disk: the write-ahead log

The newest records of the append-only file, newest first. Every line was fsynced before the server replied.

…

This file is the queue. On restart the server replays it: each ENQUEUE inserts, each DEQUEUE deletes. What remains is exactly the undelivered jobs.

API reference
CallMeaningTry it
POST /enqueueAdd a message. 201 + the stored message. curl -X POST localhost:8080/enqueue -d '{"payload":"hi","priority":5,"delay_seconds":0}'
POST /dequeueTake the next message. 200 + message, or 204 if nothing is visible. Destructive. curl -X POST localhost:8080/dequeue
GET /messagesRead-only snapshot of both lists, in exact order. curl localhost:8080/messages
GET /walRead-only tail of the write-ahead log. curl localhost:8080/wal
GET /statsCounts: total / ready / delayed. curl localhost:8080/stats
GET /healthLiveness probe. curl localhost:8080/health
